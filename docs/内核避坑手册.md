# WinDOS 内核避坑手册

> 这份文档的目的：**下次遇到同样的现象，不用重新研究。**
> 每条格式统一：**现象（日志/屏幕长什么样）→ 根因 → 改哪几行 → 验收判据**。
> 更详细的背景留在 `hermes` 技能 `windos-uefi/references/` 下（本文件是"出问题时的第一张表"）。

适用：UEFI 64 位 WinDOS（`src/main.rs` 引导器 + `kernel/` C++ 内核）。
历史 BIOS 版本（32 位、软盘引导）在 <https://github.com/boonxiong2/WinDOS-Legacy>。

---

## 0. 排查方法论（比任何具体结论都值钱）

1. **先探针，后结论**。别猜：写 3 行探针打印寄存器/签名/状态位，看结果再动手。
   *反例*：曾经连续十几轮"猜 QEMU IDE 有问题"，真凶却是 `io.h` 少了个 `volatile`（见 §5.1）。
2. **写已知值再读回**：验证任何"寄存器/端口能不能用"——`out8(0x173,0x5A); in8(0x173)` 期望 `5A`。两行代码自证，不需要懂硬件。
3. **日志必须分级**：`[KERNEL/INFO]`、`[KERNEL/CRITICAL]`、`[UEFI/INFO]`、`[UEFI/CRITICAL]`。禁止 `K1/K2` 式临时检查点。
4. **一次只改一处**，每处都留一条能验的日志。
5. **崩溃现场三件套**：串口日志（停在哪个 `[xx]` 之间）+ `info registers`（`CPL`/`CS`/`SS`/`CR2`）+ 屏上最后画面（`screendump`）。
6. **单 QEMU 实例**；`-no-reboot` 让三重故障直接退出而不是静默重启掩盖现场。
7. **自动输入用 `sendkey`**（小写；`sendkey ret` = 回车），别手点。
8. **视觉验证不能自称通过**——只有人能看屏幕说"OK 了"。

## 1. 引导链（UEFI）

### 1.1 表偏移：全都要按规范值，别照抄"网上经验"

`EFI_SYSTEM_TABLE`：`RuntimeServices @0x58`、`BootServices @0x60`（**这两个就是规范值**，不是 OVMF 特例）。

`EFI_BOOT_SERVICES`（表头 24 字节 + 中间有一个 `VOID *Reserved`，漏掉就整体错位）：

| 偏移 | 函数 | 偏移 | 函数 |
|---|---|---|---|
| 0x28 (40) | AllocatePages | 0x98 (152) | HandleProtocol |
| 0x38 (56) | GetMemoryMap | 0xA0 (160) | *Reserved* |
| 0x40 (64) | AllocatePool | 0xE8 (232) | ExitBootServices |
| 0x68 (104) | SignalEvent | 0x140 (320) | LocateProtocol |
| | | 0x168 (360) | SetMem |

**权威对照源**：TianoCore `MdeModulePkg/Core/Dxe/DxeMain/DxeMain.c` 里的 `mBootServices` 初始化表——
**每个条目都带 `// 函数名` 注释**，逐行数就能核对。

- **现象**：启动即黑屏 + QEMU 直接退出（三重故障）。
- **根因**：偏移写错会调用到**功能完全不同的函数**。真踩过的错：`360` 当 GetMemoryMap → 实际调了 **`SetMem`**，
  参数错位成 `SetMem(Buffer=NULL, Size=&map_sz(栈地址, 几百 MB), Value=…)` → 从地址 0 开始涂掉几百 MB 内存
  （内核镜像、memdisk 缓冲、BootInfo、页表、**正在用的栈**全没了）→ 跳内核即三重故障。
- **修法**：偏移改成 `56 / 64 / 232`；顺手核对 `AllocatePages=40`、`LocateProtocol=320` 都对（这两个一直是对的，
  能证伪"整张表读歪了"这种误判）。
- **判据**：`[UEFI/INFO] EBS OK`（= 返回 0/EFI_SUCCESS）。

### 1.2 ExitBootServices：ImageHandle 要真，MapKey 才是会咬人的那个

- **现象**：`ebs ret=0x8000000000000002`（`EFI_INVALID_PARAMETER`），或忽略返回值硬跳 → 随机崩。
- **根因**：
  - `ImageHandle` 必须是**调用映像自己的句柄**（`efi_main` 的第一个参数 `rcx`）。我们的入口是 `#[unsafe(naked)]`
    手动 prologue，**只存 `rdx`(SystemTable) 就会拿不到 ImageHandle** → 只能被迫传 SystemTable。
  - `MapKey` 是内存图指纹：**取图之后任何一次分配都会让它作废**，EBS 直接拒收。
  - ⚠️ 但别把"不传真句柄一定挂"当诊断依据：**EDK2/OVMF 的 `CoreExitBootServices` 压根不校验 ImageHandle**
    （只做三件事：发 `BeforeExitBootServices` 事件 → `gTimer->SetTimerPeriod(0)` → `CoreTerminateMemoryMap(MapKey)`）。
    规范要求传真句柄，只是因为别的固件可能校验。
- **修法**（`src/main.rs`）：
  1. `naked_asm!` 里除了 `mov [rax], rdx` 再补 `mov [rax], rcx`（存到全局 `IH`）；
  2. 所有分配（memdisk 缓冲 → 内核 16MB → BootInfo）**全部排在取图之前**；
  3. `GetMemoryMap` 探大小 → `AllocatePages` 分配缓冲 → **再取一次**拿真 key → `ExitBootServices(ih, map_key)`；
  4. **有界重试（8 次）**，失败就重新取图（`loop { if ebs()==0 break }` 在 key 失效时是死循环）；
  5. EBS 成功后 **`cli`**。
- **为什么必须 `cli`**：EBS 拆掉的是固件**定时器**，固件 **IDT 不会被重置**。内核在装上自己的 IDT/PIC 之前有一段
  长循环（本项目是填满 4MB 显存），这期间来一个中断就落进固件处理程序 → 用我们的 GDT 执行固件代码 → 三重故障。
- **判据**：`map sz=0x1860 / desc sz=0x30 / map key=0x7d9 / EBS OK`。

### 1.3 问 UEFI"我从哪块盘来"（别猜盘）

- **现象（多盘机器）**：读不到 `memdisk.img`，或者更阴——读到**另一个卷里的同名旧文件**。
- **根因**：用 `LocateProtocol(SimpleFileSystem)` 拿到的是**"任意一个"**文件系统实例。
- **修法**：`HandleProtocol(ih, LoadedImage_GUID, &li)` → `li->DeviceHandle`（`@24`）→
  - `HandleProtocol(devh, SimpleFileSystem_GUID, &fs)` → **一定是自己那个卷**；
  - `HandleProtocol(devh, DevicePath_GUID, &dp)` → 解析出**控制器类型 / PCI 位置 / 分区起点**。
- **DevicePath 节点**（`Type(1) SubType(1) Length(2) Data…`，`Length==0` 或 `Type==0x7F` 结束）：

| Type/SubType | 数据 | 取什么 |
|---|---|---|
| Hardware 0x01 / ACPI 0x02 | HID(4) UID(4) | **UID = PCI 总线号** |
| Hardware 0x01 / PCI 0x01 | Func(1) Dev(1) | **dev/func** |
| Messaging 0x03 / 0x01 ATAPI·0x10 SATA·0x12 NVMe·0x05 USB | — | **控制器类型**（还带 ATA 的 Primary/Secondary、Master/Slave） |
| Media 0x04 / HardDrive 0x01 | PartNum(4) **PartStart(8)@+8** **PartSize(8)@+16** | **分区起始 LBA + 扇区数** |

- ⚠️ **易错**：`part_lba` 是"**装着这个文件的物理分区**"（QEMU 实测 = 63），**不是**镜像文件内部那个 MBR 分区（= 128）。
- **判据**：引导器打 `ctrl kind/pci addr/part lba/ch/dv`，内核打出**同一组值**（证明交接成功）。

### 1.4 从 ExFAT 读内核（`exfat_find_kern`）

- 根目录项：`0x81` 文件 + `0x85` 流扩展（首簇 `@+16`、数据长度 `@+24`）+ 名字条目 `0xC0|n`；
  跳过判断用 **`nt & 0xC0 == 0xC0`**（`nt & 0x40 == 0` 是错的，会跳过所有文件名）。
- **已知局限（真实短板，未修）**：`fat_off` 解析了但**没使用**（编译器一直在警告 `unused variable: fat_off`），
  数据是按"首簇 + 长度"**连续读**的 → **KERNEL.BIN 一旦跨不连续簇就会读错**。
  目前镜像是我们自己生成的、必然连续，所以能跑。修法：沿 FAT 表跟簇链（`fat_off` 就在手边）。
- 名字条目**只读了第一段**（`off+64`）→ 超过 15 字符的名字认不出（`KERNEL.BIN` = 10 字符，未受影响）。
- 镜像上限：引导器缓冲 `mb_total = 0x40000`（256KB）→ `tools/mkmemdisk.py` 里带护栏，
  超了会明确报错并提示改哪个常量。

## 2. 内核早期（顺序 + clang -O2 陷阱）

### 2.1 `_start` 的正确顺序（这个顺序错了必翻车）

```
cli → UMIP(先 CPUID 门控再写 CR4) → 记 CR0/CR3/CR4 → 清 BSS → 装 GDT → 翻页表 US 位
    → 设 LSTAR(syscall 入口) → 初始化显示/图层/登录窗 → 装 IDT/PIC/PIT → sti
```

- **`sti` 必须在 TSS.RSP0 设置之后**：否则中断触发时切到未设置的 RSP0（垃圾栈）。
- **改页表前要清 `CR0.WP`**（否则写只读的页表页本身 #PF），改完恢复。
- **改完必须 `mov cr3` + `invlpg` 刷 TLB**，否则 Ring3 还走旧的 `US=0` 表项。

### 2.2 "用户区上界"必须按 `_bss_end` 推导，禁止写死

- **现象**：登录进 Ring3 后立刻崩；或 `syscall` 报指针越界。
- **根因（两处同一个病）**：
  1. 页表 US 位只翻了前 8MB（`pdt[0..3] |= 4`）——而 `.bss` 已 10.6MB，**用户栈落在 10.8MB**
     → Ring3 第一条 `push` 就 `#PF`，**errcode `7 = P|W|U`**（U 位 = 没给用户权限）；
  2. syscall 指针校验写死 `0x800000` → `.bss` 涨过 8MB 后会把**合法用户指针全判越界**
     （现象：`[KERNEL/USER_API/EXCPTION] Pointer DIDN'T in user mem area`）。
- **修法**：
  ```c
  extern "C" u8 _bss_end;
  u64 be; __asm__ volatile("lea %1, %0" : "=r"(be) : "m"(_bss_end));
  for (u64 i = 0; i <= (be >> 21); i++) if (pdt[i] & 1) pdt[i] |= 0x4;   /* 只翻已存在的 PDE */
  u64 lim = (be + 0x1FFFFF) & ~0x1FFFFFull;                              /* 指针校验上界 */
  ```
- **判据**：`[KERNEL] bss … sz=00A73480` → `US bits set` → Ring3 里能跑不崩。

### 2.3 clang -O2 陷阱清单（每条都真实踩过）

| 现象 | 根因 | 修法 |
|---|---|---|
| 轮询状态位**永远不变**、读同一端口总返回同一个值 | **端口读 asm 没有 `volatile`**（有输出操作数 → 被当纯函数 CSE/提出循环） | 见 §5.1，全部 `volatile` + `"memory"` |
| 中断门地址 = 垃圾（`gate20=0x3BE6C37F`），中断不触发 | `KERN_BASE + h` 内联时 `rax` 被复用 | `volatile u64 KB = KERN_BASE;` 强制重载 |
| 阴影循环死循环 / `E06` | 循环里用**三元表达式** | 改显式 `if/else`；必要时 `#pragma clang loop unroll(disable)` |
| `continue` 后计数器不递增 → 死循环 | 复杂 `if` + `continue` 被优化 | 改成 `if` 包住整个循环体 |
| `if` 判断寄存器值被优化掉 | **register-asm 变量**是 UB | 用显式 `movq %rax, %0` 读 |
| 刷新背景时 #PF（`CR2` 固定、多处 RIP） | 内联后基址寄存器被复用成调用点垃圾值 | 背景写用 `volatile u32 *v = ctl->vram;` 强制每次重载 |

### 2.4 崩溃处理程序（死屏）自身必须 crash-safe

- **现象**：崩了但看不到现场；或者递归到栈耗尽；或者死屏上什么也没有。
- **根因**：① `ds()` 信任 `g_fb/g_stride/disp_w()/disp_h()`——**它们就在 .bss 里紧挨着大缓冲，往往正是被踩坏的那批**；
  ② 没有防重入 → 崩 → `ds()` → 又崩 → 递归，把真正的现场盖掉。
- **修法**：`static volatile int entered`（进了就 `cli; hlt` 死等）+ 显存指针/几何合法性检查
  （规范地址 + 4 字节对齐 + 宽高/步幅范围），**不可信时只打串口不画屏**。
- **判据**：`[KERNEL/CRITICAL/INFO]BSOD DREW` 或 `BSOD SKIPPED (display state unusable)`——两者都是"正常工作"。

## 3. 中断 / 输入 / 图层

- **键盘**：`0xAE` + `0xF4` 才使能；Set2 扫描码表；`isr21` 的 EOI 是 **`0x61`**（特殊）；
  `isr2c` 的 EOI 是 `0xA0,0x20`；**键盘 init 必须早于鼠标**（否则吃掉 `0xFA` 把鼠标驱动卡在 phase 0）。
- **图层 `sheet_*` 不可重入**：鼠标中断（`isr2c`）自己在动图层表，主流程也在动。
  **现象**：时而崩时而不崩的 #PF（野指针写）。**修法**：所有主流程里的 sheet 段用 `io_cli()/io_sti()` 包住
  （本项目 3 段：桌面全刷+登录窗创建整段 / 登录拆除→sysret 窗口 / 输入回显刷新）。
- **缓冲尺寸必须与"最大模式"一致**：`back_buf[800*600]` 按 1280×800 用 → **越界写 2.1MB**，
  糊掉 `cur_buf / kstack / login_wbuf / g_fb / tss / user_stack`。规则：数组尺寸和循环上界必须**同源**。
- **阴影 = 合成减**：半透明标记像素 = 高位非 0、低字节 = 层数；下层 RGB 同减、下溢 clamp。
  **光标颜色高位必须是 `0x00`**（白 `0x00FFFFFF`、黑 `0x00000000`），否则被当成阴影标记 → 光标变黑。
- **刷新联动**：半透明像素刷新时登记 `map=0`、强制绘制、并只重画"高于刷新层"的阴影层，否则重复叠加变黑。

## 4. 用户态（Ring3）

- **GDT 用户数据段字面量必须写满 16 位**：
  `0x00CFF2000000FFFF` ✅ vs `0x00CFF20000FFFF` ❌（14 位 = 7 字节 → 左补零 → access 字节被顶成 `0xCF` = S=0/type=F 系统段）。
  **现象**：`sysret` 能过（它不读 SS 描述符），但**第一发中断回到 Ring3 时 `iret` 一读 SS 就 #GP**——
  `isr.S` 注释里的错误码 `e=0x20` 正是选择子 `0x23 & 0xFFF8`。**这是"进不去用户态"的真凶。**
- **`jump_user` 必须手动设 `RSP`**（`sysret` 不设栈）并给 `R11 = 0x202`（IF=1，否则进 Ring3 后中断永久关闭）。
  验证：`info registers` → `CPL=3`、`CS=002b DPL=3 CS64`、`SS=0023 DPL=3 DS [-WA]`、`RFL=0x202`，
  且按键时 `i21` 计数会涨（= Ring3 里中断活着）。
- **安全模型**：`IOPL=0` + `UMIP`（**必须先 CPUID 门控**，QEMU 默认 CPU 不支持，直接写 CR4 会 #GP）+ IDT 页 `US=0`
  + syscall 指针校验。Ring1 不用（现代 OS 只用 Ring0/3，分级用软件分级）。

## 5. 存储与文件系统

### 5.1 端口 I/O 必须 `volatile` + `"memory"`（**最坑的一条，误判了好几天**）

```c
/* ✗ 错：in8 有输出操作数却不是 volatile → 被当纯函数（CSE / 提出循环 / 与写重排） */
static inline u8 in8(u16 p) { u8 v; __asm__("inb %1,%0":"=a"(v):"dN"(p)); return v; }
/* ✓ 对 */
static inline u8  in8 (u16 p) { u8  v; __asm__ volatile("inb %1,%0":"=a"(v):"dN"(p):"memory"); return v; }
static inline u16 in16(u16 p) { u16 v; __asm__ volatile("inw %1,%0":"=a"(v):"dN"(p):"memory"); return v; }
static inline u32 inl (u16 p) { u32 v; __asm__ volatile("inl %1,%0":"=a"(v):"dN"(p):"memory"); return v; }
static inline void out8 (u16 p, u8 v)  { __asm__ volatile("outb %0,%1"::"a"(v),"dN"(p):"memory"); }
static inline void out16(u16 p, u16 v) { __asm__ volatile("outw %0,%1"::"a"(v),"dN"(p):"memory"); }
static inline void outl (u16 p, u32 v) { __asm__ volatile("outl %0,%1"::"a"(v),"dN"(p):"memory"); }
```

- **为什么 `out8` 不加没事**：GCC/clang 规则——**没有输出操作数的 asm 隐含 volatile**；`in8` 有 `"=a"(v)` 就不隐含。
- **现象（三合一）**：① 轮询 DRQ 超时（循环只读了一次）② PCI 配置空间连读多次返回同一个值
  ③ 写寄存器后读回不对（读被提到写之前）。
- **误判记录**：曾据此得出"**QEMU IDE PIO 已知损坏、DRQ 永不置位**"——**结论是错的**，真凶就是这里。
- **判据**：`ata port chk lba_lo reg: 5A->5A  A5->A5`。

### 5.2 ATA PIO 实盘读写配方（LBA28）

```
等 BSY 清(base+7 bit7=0) → 选盘 out8(base+6, 0xE0|LBA高4位) → 读状态 4 次(延迟)
→ 写数量 base+2 → LBA base+3/4/5 → 命令 out8(base+7, 0x20 读 / 0x30 写)
→ 轮询 DRQ(base+7 bit3)；bit0=ERR 报错；读到 0x00/0xFF = 无盘
→ 读/写 256 个 u16（数据口 base+0）
→ 写操作：等 BSY 清 + FLUSH CACHE(0xE7) 才算落盘
```

- 端口：Primary `0x1F0-0x1F7`（控制 `0x3F6`）、Secondary `0x170-0x177`（控制 `0x376`）。
- **小文件写盘用读-改-写**（读整扇区 → 覆盖 → 写回），别整扇区清零写。
- **判据**：`ATAread … ret=0  oem=4D 53 57 49 4E 34 2E 31  aa55=55 AA` ← 真 FAT 引导扇区 `"MSWIN4.1"`。

### 5.3 按**内容签名**识别设备，不按盘位顺序

给盘一个签名（如 LBA0 = `"WINDBG01"`），扫 4 个 `(通道,盘位)` 组合找签名 → 换机器/换线/换插槽照样能找到。
日志盘就是这么做出来的：`logdisk ch=1 dv=1 wr=0 rd=0 WRITE_OK`。

### 5.4 QEMU IDE 布局（排查用）

- `-device ide-hd,drive=X` 默认挂**二级通道 `ide.1`**；`info qtree` 看盘位，`info pci` 看控制器。
- PIIX3 IDE = `8086:7010`，**只有 BAR4** → **兼容模式**，传统端口 `0x1F0/0x170` 才是正路。
- 盘位**别猜**：用 DevicePath 里的 `Ata(Secondary,Master)` 节点。

### 5.5 `fs/exfat.cpp` 的两个纪律

1. **别再引入"测试替身"**：曾有 `#define ide_read_sector mem_read_sector` 把整个 FS 层重定向到内核内嵌的
   80KB 内存镜像 → 所有 `[FS] init OK / write OK` 都是假象，**真盘一次没碰过**，把驱动问题藏了好几天。已删除。
2. **写路径的读-改-写边界**：数据、位图、目录簇三处写入都必须落到真盘（数据按扇区读-改-写）。

## 6. 时钟

- **不要用 CMOS RTC**（`0x70/0x71`）：QEMU 下读出垃圾（时=分=秒、无效 BCD `85/86`），试过 NMI 屏蔽/延时/稳定读循环都无效。
- **用 UEFI `GetTime`**（引导器阶段，EBS 之前）：`SystemTable+0x58` → RuntimeServices，`RT+0x18` = `GetTime`，
  `EFI_TIME` 16 字节：`[Year u16][Mon][Day][Hour][Min][Sec][Pad][Nano u32][TZ i16][DL][Pad2]`。
  内核用 `GetTime 初始秒 + PIT 累加` 走字。
- 注意 QEMU 的 PIT 实测约 37Hz（不是 100Hz），想精确要校准或换 HPET/APIC。

## 7. 真机移植清单（QEMU 能跑 ≠ 真机能跑）

按踩中概率排序：

1. **Secure Boot 会拒绝未签名的 `BOOTX64.EFI`**（BIOS 里关掉，或签名）。
2. **无 PS/2**（笔记本/新主板）→ 键盘鼠标全废，GUI 成砖 → 需要 xHCI USB HID 驱动。
3. **看门狗**：真机固件常武装看门狗，EBS 只关定时器不关它 → 几分钟后自动重启 → EBS 前调 `SetWatchdogTimer(0,0,0,NULL)`（`bs+0x100`）。
4. **显存像素格式**：现在写死 BGRx；真机会遇到 RGBx（红蓝互换）或 `PixelBltOnly`（**没有线性帧缓冲**，只能用 `Blt()`）→ 读 `Mode->Info->PixelFormat` 分派。
5. **分辨率上限**：`lm_map`/`back_buf` 固定 `1920*1080` → 4K 模式（3840×2160）会**越界写约 25MB** → 要按 `hr*vr` 裁剪或动态分配。
6. **`EFI_FILE.Read` 可能分次返回**，我们只读一次 → memdisk 被截断 → 要循环读到 EOF。
7. **NVMe/MMIO**：现在靠继承固件页表；真机 64 位 BAR 常 >4GB，固件页表未必映射 → 读 MMIO 会 #PF → 自己建页表 + 映射 UC。
8. **显示慢**：MMIO 未设 WC（PAT/MTRR）→ 逐像素写显存极慢。
9. **关机/重启**：EBS 后 `RuntimeServices` 仍可用 → `ResetSystem`（`rt+0x68`）。
10. **多 GPU**：`LocateProtocol` 只拿第一个 GOP 实例 → 混合显卡笔记本可能画到"没人看的屏" → `LocateHandleBuffer` 遍历挑选。

## 8. 一屏速查（看到这些就算通过）

| 检查 | 期望 |
|---|---|
| 引导器 | `map key=0x7d9` → `EBS OK` → `jump kernel` |
| 内核早期 | `US bits set` → `LSTAR set` → `gate20=<非垃圾值>` → `[int] sti` |
| 心跳 | `[KERNEL/INFO] t=200/400/… SYSTEM ALIVE`（PIT ~37Hz） |
| 真盘 | `ATAread … ret=0 … aa55=55 AA`；`logdisk … WRITE_OK` |
| 端口 asm | `ata port chk lba_lo reg: 5A->5A  A5->A5` |
| Ring3 | `J3` → `HELLO FROM RING3`；`info registers` → `CPL=3`、`SS =0023 [-WA]`、`RFL=0x202` |
| 死屏 | `BSOD DREW`（或 `BSOD SKIPPED`）——两者都算"崩溃处理正常工作" |
